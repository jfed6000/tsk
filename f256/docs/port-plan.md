# Texas Shitkickers on the F256: the port plan (P4)

*How the browser game (`game/js/brawler.js`) becomes a NitrOS-9 Level 2 program. It follows `../../game/port-guide.md`;
this file records only what is specific to this game. Started 2026-10-12.*

## What kind of port this is

An original game, so there's no arcade listing to transcribe. The **browser prototype is the reference**: its
behaviour, its numbers and its art. Art reaches the F256 only through the exporter (`tools/export.py`), never by
hand. Game logic is **translated by hand** from `brawler.js` into 6809, one system at a time. Each system is checked in
MAME against the browser before the next starts (port-guide §14: each part confirmed before the next).

## The program

One program module, **`tsk`**, assembled from:

| File | What |
|---|---|
| `src/tsk.asm` | The module header, the includes, the build switches |
| `src/data.a` | The data area: direct-page variables first, then the larger tables |
| `src/platform.a` | Start-up, asset loading, display set-up, the frame loop, input, pause, Cleanup (from Joust's `platform.a`) |
| `src/hero.a` | The Shitkickers: input → state machine → physics → animation |
| `src/enemy.a` | The skeleton gunslinger, its bullets and loose skulls, particles, hits and KOs, the hero's attack check, the autopilot |
| `src/draw.a` | The display list: depth sort, metasprite records, shadows, shake, the camera and the three maps' scroll |
| `src/tsktabs.a` | Generated by the exporter: the hero's attack box per frame (`HitTab`) |
| later | coyote and dillo, `boss.a` (Two-Bit), `stage.a` (waves, pickups), `hud.a`, `sound.a` |

`tskview` stays as the graphics harness.

## Numbers

- **One pass per 60 Hz tick** (`F$Sleep` X = 2). If passes start overrunning, move to the SOL clock (port-guide §12.2).
- **Fixed point 12.4** for positions and velocities: 16-bit words, 4 fraction bits. x covers 0-4095 px (a stage is at
  most 2400), z is 0-80, h is height above the floor.
- Browser constants (per second, at 120 Hz) convert to per-tick 12.4:

  | | Browser | Per tick | 12.4 |
  |---|---|---|---|
  | Walk x | 105 px/s | 1.75 px | 28 |
  | Walk z | 62 px/s | 1.03 px | 17 |
  | Jump | 360 px/s | 6 px | 96 |
  | Gravity | 1150 px/s² | 0.32 px | 5 |
  | Flying kick | 170 px/s | 2.83 px | 45 |
  | Stomp drop | 560 px/s | 9.3 px | 149 |

  A jump peaks at 96² / (2×5) / 16 = 57.6 px (browser: 56).
- **Screen position:** x = world x − camera, y = FLOOR.Y + z − h. A sprite record adds 32 to both (the visible screen
  starts at 32,32).

## The display: sprites

- A **display list** each pass: one entry per character (depth z, CTRL byte, frame number, screen x, y). It is sorted
  nearest-first, because sprite 0 is on top. Each entry's frame expands into its cells (`frames.bin`), one record per
  cell. The record table is registered once (`SS.SprReg`), and **one `SS.SprPush`** sends records 0 to the highest
  used this pass or last.
- **Shadows** go after all the characters, so they're always behind them: one record each.
- Mirrored frames are frame + `<group>.Mir` (`tskassets.d`).

## The display: tiles and CLUTs

- **Tile layers:** the street (map 2) is layer 0, the hill layer 1, the sky layer 2. They scroll at 1, ½ and ¼ of
  the camera (`SS.TmScrl` ×3 a pass).
- **CLUTs:** 0 sprites, 1 hit flash (white), 2 ghost (spare), 3 tiles. The tile CLUT and its lightning copy live in an
  asset block that is mapped only for the `SS.ClutWrite`.

## Memory

- **Assets** are in blocks from `SS.GfxAlloc` and loaded one 8K window at a time.
  - Boot Hill: tiles 18 blocks, sprites 65, maps 1, CLUTs 1.
  - Stage art is loaded per stage, so Main Street replaces Boot Hill's.
- **Data area:** 8.8K since sprint 2 (96 sprite records, the enemy, skull, bullet and particle tables), with the frame
  table (3.3K) in it so `BuildChar` reads it directly. When more characters push the frame table past ~4K, it moves to
  a block mapped once at start-up.
- **Module:** the budget is 40,192 bytes (port-guide §3); `make budget` fails above it.

## Input

- **`SS.LiveKeys`** once a pass gives held keys: the arrows from the sense bits, Z or space to jump, X to kick, C for the
  side kick, Q to quit. Jump, kick and side kick are edge-detected by the game.
- **Two buttons** (decided): side kick = back + kick, with C a shortcut.
- **SNES pads** (`SS.Joy`) come with the pad harness (P2 task 697); the guard rules are in port-guide §9.
- **Demo mode:** `tsk d` plays a scripted input sequence. That's the MAME test path, since held arrow keys can't be
  scripted reliably from Lua.
- **Autopilot:** `tsk b` fights (brawler.js `?bot`: into the nearest enemy's lane, up close, kick); `g` makes him
  untouchable (`tsk bg`). The MAME test path for combat (`make mamebot`).

## Order of work

1. ✓ **Skeleton + the hero walking on Boot Hill:** start-up, loading, the three maps, the hero's state machine (walk,
   jump, the 3-kick combo, side kick, flying kick, stomp, land, taunt), camera, depth-sorted display list with a
   shadow, demo mode. *(sprint 1, 2026-10-12: `tsk` is 2.9K; verified on the host 6809 and in MAME)*
   - The port found **two bugs in the browser game**, fixed on both sides: a jump press also stomped at once (he
     couldn't jump at all), and the press that started a snap kick also queued the next (one tap gave two kicks).
2. ✓ **Enemies and combat:** the skeleton gunslinger (rise, approach, aim, shoot, reload, stagger, knockdown, get up,
   skull knocked off and the headless body groping for it, skulls kicked down the lane, KO shatter), its bullets
   (dodge them, or kick them out of the air), the hero's attack boxes from the exporter, damage, the hero's hurt state,
   lives, the stomp's shockwave, sparks and dust. **Combat feel:** hitstop, the white hit flash (CLUT 1), shake (the
   sprites and all three maps). *(sprint 2, 2026-10-13: `tsk` 7.0K; verified on the host 6809 and in MAME)*
   - Until the waves come, a gang of two or three skeletons rises whenever the street is empty, and the screen
     locks while any are about (the camera holds, enemies stay on screen, the hero can't walk off the right edge).
   - Not yet: dillos (moved to sprint 3, with waves), the stomp's ring, the gun a skeleton sometimes drops (pickups).
   - The port found **a third browser bug**, fixed on both sides: a hit in mid-air froze the hero's height (the hurt
     state had no gravity), so he could be left walking in the air.
   - Cost: about 14K cycles a pass on average, 49K at the worst (a KO: eleven particles), of a ~105K tick.
3. ✓ **Boot Hill, whole:** the opening (rising from Ringo's grave, the hat hopping onto his head), the four waves
   and their screen locks and GO, the dillo, barrels and pickups (beans, the whip, the six-shooter; a skeleton's
   dropped gun), the HUD (health, score, lives, weapon, the enemy's name and bar, the combo), popups and titles,
   Two-Bit (swing, clods, dig-tunnel-pop, dizzy, raising the dead at half health), the clear, TO BE CONTINUED,
   game over, and starting again. *(sprint 3, 2026-10-14: `tsk` 17.2K, data 11.2K; verified on the host 6809 and in
   MAME)*
   - **Text** is sprites: fixed words are exported frames (TX.*); the HUD and points popups are drawn by the 6809
     into 16 dynamic cells, two blocks allocated after the sprite art (`hud.a`). One HUD part is redrawn a pass, and
     a popup's text is drawn on the pass after the hit, so the worst pass stays about 70K cycles.
   - **Two-Bit** is an enemy slot of type `TY.Boss` (`boss.a`), so hits, the HUD and the autopilot need nothing new.
   - New arguments: `tsk k` starts at Two-Bit; `tsk b` / `tsk g` as before (the autopilot now walks on, breaks
     barrels and picks up weapons).
   - Cost: about 17K cycles a pass on average. The worst seen is 98.6K, on Two-Bit's KO, which shatters the dead he
     raised in the same pass. That's close to the ~105K tick; if it drops a frame on the K2, spread GangDown over
     passes.
   - Not yet: the grab, knee and throw (the browser's walk-into-a-staggered-enemy), the stomp's ring, the help
     screen, sound.
4. ✓ **The title screen and sound** *(sprint 4, 2026-10-14: `tsk` 18.8K)*:
   - **Music on the SAM2695** (General MIDI). It's composed as code (`tools/compose.py` → `game/music/*.mid`; any DAW's
     `.mid` will do instead), converted by `tools/midi2tsk.py` into one 8K block a song (records of wait, length and
     MIDI bytes on 60 Hz frames, with running status and a loop point), and played by `src/snd.a`'s sequencer, one
     song at a time from its mapped block.
   - **The songs:** the title "Shitkicker Shuffle" (fast E boogie: overdriven guitar, slapped upright, honky-tonk
     piano, harmonica); "Boot Hill" (slow minor, tremolo guitar, whistle, a heartbeat on the floor tom); and the
     clear and game-over tags. `tools/render.py` renders them through fluidsynth to MP3 for previews and for the
     browser.
   - **Sound effects** use GM drum-kit notes on channel 10, plus a gunshot, a whoosh and a timpani on channels 13-15,
     with a queue for note-offs and delayed notes. The hero's sounds come from `SetS` (a per-state table); the rest
     sit where brawler.js calls `sfx()`.
   - **Output:** one routine, `MidiFlush`, once a frame, writes straight into the MIDI FIFO at $FF30 (whose bytes
     also feed the 2695), checking the FIFO's fill. **Decided (user, 2026-10-14): "I think direct is ok for sound."**
     It's an absolute-I/O exception like Joust's VS1053. `MidiPath=1` builds write to `/mi` instead (the Level 2 boot
     has no `/mi`; MIDrv is in `level1/wildbits/modules`), kept but unused.
   - **Verified:** the host 6809 plays all 759 notes of Boot Hill's theme exactly, through the loop, against a
     reference player. In MAME a Lua tap on $FF31 caught all 671 notes of the title theme at a constant offset, and
     `make mametitle` turns that capture into `mame/midi.mid` to render and hear.
   - **The title screen** (`src/title.a`): the logo, the tagline, the high score (drawn into the HUD strip), PRESS
     JUMP, the Shitkickers taunting, the camera drifting along Boot Hill. Jump starts a game. After 20 s the attract
     mode runs the autopilot for up to 50 s (any button ends it). The end and game over go back to the title.
   - **Found and fixed:** a label rename in step 4 of sprint 3 had turned the direct-page variable `bh1` into a code
     label, so the whip's hit box wrote over a random variable. `tools/dpcheck.py` now fails the build on any `<name`
     that isn't a direct-page variable.
5. ✓ **Main Street** *(sprint 5, 2026-10-14: `tsk` 20.4K, data 12.2K)*: the whole game, Boot Hill then Main Street,
   then TO BE CONTINUED.
   - **Per-stage art:** the exporter packs each stage's tiles and maps (`tiles_bh/ms.bin`, `maps_bh/ms.bin`), and
     `stage.a`'s `LoadStage` reads them into the same blocks when a stage starts (the screen blank meanwhile).
   - **Sprite banks:** the shared cells (hero, skeleton, dillo, effects, props, text: 732) stay loaded; each stage's
     own (Boot Hill's Two-Bit 113, Main Street's mangy gang and tumbleweed 88) load at cell `SPR.Base`.
   - **Memory:** at the most about 1.14 MB: shared sprites 736K, an overlay 113K, a stage's tiles 166K, maps,
     dusk CLUTs (61K), music, HUD cells. That's over port-guide's 1 MB line, flagged to the user; the K2 has 2 MB.
   - **A stage table** (`StgTab`): width, maps, tile sets, flags (the opening, lightning, dusk), song, waves,
     barrels, titles, files. `tsk m` starts on Main Street.
   - **The mangy coyote** (`TY.Coy`): walks in, takes a spot 36 px beside you, winds up 0.42 s, swings (2 to you if
     you're in front of it, within 44 px). 9 health, 300 points. Skeletons walk in on Main Street rather than
     rise.
   - **Night falls** with each wave: 61 tile CLUTs from the exporter, 1% apart (the lights kept lit), faded over
     CLUT 3 a shade every 8 passes, so a wave's change creeps in over about 1.6 s. The first cut's 13 steps of 5%
     looked abrupt on the K2.
     Tumbleweeds and dust motes in the low sun (`amb.a`).
   - **Music:** Main Street plays "Graveyard Boogie".
   - **Cost:** the worst pass in a whole game is now 77K cycles. Two-Bit's KO takes his gang down one a pass;
     particle allocation is round robin and gives up at once when the table's full.
   - **Fixed along the way:** the stage titles fetched the stage record through Y, which is the sprite-record
     pointer while drawing, so at Main Street's clear the record clearing wrote zeros over the program.
6. The grab and throw, the pad harness, co-op, a Main Street boss.

Each step has a demo script and a MAME check against the browser; the K2 run is the user's.

## Testing

- **`make host`** (`tools/hostrun.py`) runs the module on the host 6809 (Tempest's `tools/cpu6809.py`), with the OS-9
  calls answered in Python and the asset files read from `assets/`. It prints any variables from `tsk.map` pass by
  pass (`--watch hst,ht,hx,hh --every 1`) and the sprite records a pass pushed (`--records N`). It proves logic, not
  timing. This is where bugs are found: compare its numbers with the browser's.
- **`make mame`** runs `tsk d` in the Wildbits MAME and takes snapshots (`tools/tsk.lua`), proving the display.
  **`make mamebot`** runs `tsk b` (`tools/tskbot.lua`), a snapshot every 6 frames, to catch flashes and sparks.
- `hostrun.py --args bg --enemies` prints the enemy table pass by pass (state, x, z, height, health, headless), and
  every run ends with the 6809 cycles a pass (average and worst; the OS-9 calls aren't counted).
- **The browser** can be driven headless the same way (a `requestAnimationFrame` shim, keys dispatched from a script)
  to check a behaviour on the reference side.
